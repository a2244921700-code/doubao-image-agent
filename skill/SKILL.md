## 铁律：比例必须先定，且必须写进提示词

豆包在提示词**没有任何比例线索时一律返回 1:1**。1:1 会把 3:1 的按钮、16:9 的场景、9:16 的竖屏背景全部塞进方形画布，四周大面白雪，素材直接废掉。

所以：

1. **用户明确说了比例** → 照用，不要擅自改。
2. **用户没说** → 按"这张图要拿去干什么"查下面的表，**不要凭感觉**。
3. **查不到对应用途** → 用 1:1，并在交付时说明"按方形出的，需要别的比例告诉我"。

实测结论（已验证，可依赖）：
- 提示词里写 `生成一张 9:16 竖版图片：...` → 输出 1520×2720，精确 9:16；
- 写 `生成一张 3:1 宽幅图片：...` → 输出 3536×1168，按钮横向铺满画布；
- **豆包接受任意比例**，不受固定档位限制，所以比例可以按需求自由定。

## 命令（在 `engine` 目录下执行，输出均为 JSON）

```powershell
node agent.mjs ratios                             # 比例查表
node agent.mjs health                             # 端口、当前对话、是否在生成
node agent.mjs launch                             # 冷启动：重启豆包并开调试端口
node agent.mjs new-chat                           # 新建对话（隔离上下文）
node agent.mjs open --conversation <id 或 url>     # 切到指定对话
node agent.mjs gen --prompt-file <txt> --title <slug> [--category <id>] [--ratio 3:1] [--reuse] [--expect 3] [--timeout 300]
node agent.mjs pick --stage <目录> --pick <1|2|3|all> --title <中文标题> [--project <项目>] [--name <模板>]
node run.mjs                                      # 交互式（人工用这个）
```

- 只写内容、不写比例交给 `gen` 时，它会自动补上比例和构图句。
- 提示词里**已经写了比例**（如"9:16"）时不会被覆盖，`ratioSource: prompt`。
- `--reuse`：不新建对话，在当前对话继续发（打回重做用）。
- `gen` 返回里必看三项：`ratio`（定了多少）、`ratioSource`（谁定的）、`ratioOk`（豆包有没有真的照做）。

## 标准工作流

1. **定比例**：查上表，确认这张图的用途 → 得到比例。
2. **写提示词**：`[主体] + [风格] + [颜色] + [背景] + [禁止项]`，比例和构图由 `--category` 自动补；也可自己在开头写死比例。
3. **出手**：`node agent.mjs gen --prompt-file ... --title ... --category <id>`。
4. **先验比例**：`ratioOk:false` 就说明豆包没照做——不要往下走，用更明确的"生成一张 X:Y 图片"重发。
5. **再验内容**：`read_image` **逐张真的看**，按下表打分。
6. **判定**：合格→7；不合格→`gen --reuse` 只发要改的点，最多 3 轮；3 轮不行换 `new-chat` 重写提示词。
7. **归档**：`pick --pick <最佳> --title <标题>`，三张都好就用 `--pick all`。
8. **回报**：文件名、尺寸、比例、选了第几张、为什么，以及淘汰原因。

## 审片清单（逐项过，任一项挂就重做）

| # | 检查项 | 不合格表现 |
| --- | --- | --- |
| 0 | **比例对不对** | 和需求用途不符、主体被塞在方形画布中间大片留白 |
| 1 | 主体对不对 | 数量、类型、动作、视角与需求不符 |
| 2 | 风格统一 | 扁平/厚涂/像素/写实串味，线宽笔触不一致 |
| 3 | 构图可用 | 主体被裁切、不居中、留白不够、比例错 |
| 4 | 颜色达标 | 指定色偏了、脏、渐变断带 |
| 5 | 画面干净 | 乱码文字、多余肢体、粘连、结构崩坏 |
| 6 | 分辨率 | 长边低于 2048 或四角有杂色 |

水印不算不合格项，交给下游 PS 处理。

## 提示词要点

```
生成一张 3:1（2048×680）宽幅横向图片：[主体]，[风格]，[颜色]，[背景]，[视角]。
构图要求：按钮横向铺满画面宽度，上下留白极少，圆角与描边完整不被裁切。
画面中不要出现任何文字。
```

- 中文即可；要"素材可用"就明确写**纯色背景 / 无文字 / 居中 / 留白**。
- 要透明底就写"纯色背景便于抠图"，别指望豆包直接给透明通道。
- 打回重做时**只写要改的点**，别把原提示词抄一遍，否则会重画整张。

## 命名规范

默认 `{date}_{slug}_{seq}` → `20261018_开始冒险按钮底图_01.png`（`config.json` 可改）。
占位符：`{date}` `{slug}` `{project}` `{seq}` `{i}`，非法字符自动替换、重名自动加后缀。归档时写同名 `.json` 侧车（提示词、比例、来源 URL、对话链接、时间）。

## 排障

| 现象 | 处理 |
| --- | --- |
| `debug port closed` | `node agent.mjs launch` |
| `chat target not found` | 客户端窗口被关，跑 `launch` 重启 |
| `composer not found` | 停在非对话页，`new-chat` 后重试 |
| `ratioOk:false` | 豆包忽略了比例，提示词开头重写成"生成一张 X:Y 图片"再发 |
| `ok:false, timedOut` | 生成超时；`status` 看是否仍在生成，或降低 `--expect` |
| 抓到缩略图 | 不该发生；查 `source` 是否含 `cgen` |

**不要并发跑两个 gen**：豆包是单窗口，会互相打断。
